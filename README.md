# Win Region Recorder · Windows 区域录屏

拖拽框选屏幕上的任意一块矩形，按你点击的时机开始 / 结束录制，输出 mp4。

录制过程中选区外侧会显示红框和一条状态条（带计时与「结束录制」按钮），所以你随时知道正在录哪里——**这两个提示都在录制矩形之外，不会被录进画面**。

## 特性

- **四步操作**：框选区域 → 确认选区 → 开始录制 → 结束录制。不用记命令行参数。
- **精确时长**：手动点结束；或在「限时(秒)」填数字自动停。
- **提示器不入画**：红框画在录制矩形外 3px；状态条自动摆到选区之外的空白处。
- **高 DPI 正确**：per-monitor DPI aware，坐标全程物理像素。4K + 200% 缩放下实测无偏移。
- **零第三方依赖**：纯 `ctypes` 调 Win32 画界面，不需要 tkinter / PyQt / Electron。唯一外部依赖是 ffmpeg。
- 录制中关闭面板也会先给 ffmpeg 收尾（写 `q` 让它正常封盘），不会留下损坏文件。

## 依赖

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| Python | 3.8+（**不需要 tkinter**，托管版 Python 也能跑） |
| ffmpeg | 放在 `ffmpeg\bin\ffmpeg.exe`（便携版直接解压进来即可），或已在 `PATH` 上 |

## 快速开始

双击 `rec_gui.bat`。面板默认出现在屏幕右上角，可拖标题栏挪位置。

| 步骤 | 操作 |
|---|---|
| ① 框选区域 | 点按钮 → 全屏变暗 → **按住左键拖出矩形**（实时显示尺寸）→ 松开。右键 / `ESC` 取消 |
| ② 确认选区 | 点「确认选区」→ 暗屏消失，选区周围出现**绿框**。不满意点「重画」 |
| ③ 开始录制 | 点「开始录制」→ 面板收起，选区外出现**红框**，下方浮出 `● REC 0:05.3 (手动结束)` |
| ④ 结束录制 | 点状态条上的「结束录制」→ 面板回来，显示文件名、大小与已录时长 |

- **限时(秒)** 填 `0` = 完全手动结束；填 `10` = 到 10 秒自动停。
- 默认输出目录：`%USERPROFILE%\Videos\Screen Recordings`，文件名 `region_<年月日>_<时分秒>.mp4`。

```bat
rec_gui.bat  --sec 10  --out D:\clips        :: 限时 10 秒自动停，输出到 D:\clips
```

## 命令行版

不需要界面时用 `rec10s.bat`（两次点击定矩形 + 精确秒数）：

| 命令 | 行为 |
|---|---|
| `rec10s.bat` | 点左上角、再点右下角 → 3 秒倒计时 → 精确录 10 秒 |
| `rec10s.bat last` | 复用 `last_region.txt` 里缓存的区域，录 10 秒 |
| `rec10s.bat pick` | 只取区域并缓存坐标，不录 |
| `rec10s.bat check` | 让捕获框在屏幕上闪 3 秒，确认区域对不对 |

```bat
python rec_region.py --sec 10 --pick --countdown 3        :: 点选 + 录
python rec_region.py --sec 10 --region "100 200 800 600"
python rec_region.py --check                              :: 只画框校验
python region_rec_gui.py --selftest "1000 700 1200 800" --selftest-sec 4
                                                          :: 自检：不碰鼠标，自动录完退出
```

## 工作原理

- **采集**：`ffmpeg -f gdigrab -offset_x X -offset_y Y -video_size WxH -i desktop`，`-c:v libx264 -pix_fmt yuv420p`。
- **停止**：向 ffmpeg 的 stdin 写 `q`。不要 `kill`，否则 mp4 的 moov box 不完整。
- **提示框**：把一个窗口的区域设成「外框减去内框」，得到一个空心边框窗口——所以框内是真空的，点击能穿透，不会挡住你在被录软件里的操作。
- **坐标口径**：进程启动即设为 per-monitor DPI aware，窗口坐标、鼠标坐标、gdigrab 偏移量三者都是物理像素，不需要任何换算。

## 实测数据（3840×2160 @ 200% 缩放）

| 场景 | 结果 |
|---|---|
| 自检录 4 秒，选区 1200×800 | 1200×800 / 30fps / 4.13s / 123 帧 |
| 限时 5 秒自动停 | 5.20s |
| 手动结束（约 25 秒） | 25.30s |
| 视频边缘 6px 条带平均色 | (248,243,249) / (255,255,255) ≠ 红框色 (234,31,33) → 提示器未入画 |

## 已知限制

- **只录单个显示器**（gdigrab 的 offset 从主屏左上角起算）。
- **不录声音**。要系统声或麦克风，用 Windows 11 自带的截图工具（`Win + Shift + R`）。
- **时长不是帧精确**：gdigrab 会补帧 / 丢帧，10 秒实测 298 帧（30fps 应为 300）。验收看容器 `duration`，别看帧数。
- 同时被 Windows 的 DPI 缩放和全屏独占程序影响：部分独占全屏的游戏窗口抓不到。

## 排错

- **录到的位置不对 / 尺寸差一半**：进程 DPI 感知没设置成功。启动后看脚本同目录的 `last_run.txt`，`coord factor k` 应为 `1.00`。
- **提示框、状态条不见了**：某些「总在最前」的应用会和本工具抢层级，工具会每 700ms 重新置顶一次。
- **界面发虚**：同样是 DPI 感知问题，见上。
